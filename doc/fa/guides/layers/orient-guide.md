# راهنمای جهت‌یابی

درِ ورودی سیستم لایه‌ها. مهارت: `/layers-orient`.

## بدانید جهت‌یابی چیست <a id="know-what-orient-is"></a>

- بازبینی سریع (audit) در هر هفت لایه، نه کاوش عمیق در یکی
- به یک پرسش پاسخ می‌دهد: کدام لایه فوری‌تر از همه به توجه نیاز دارد؟
- خروجی: یک جدول بازبینی کوتاه و یک توصیه

## سه پرسش بپرسید <a id="ask-three-questions"></a>

- موضوع دربارهٔ کدام محصول یا قابلیت است؟
- کدام چالش طراحی این را برانگیخته است؟
- کار تا کجا پیش رفته است: کاوش اولیه، طراحی فعال، اصلاح یک محصول
  موجود؟

## هر لایه را بازبینی کنید <a id="audit-every-layer"></a>

برای هر لایه یک یا دو پرسش هدفمند بپرسید و آن را رتبه دهید:
قوی / نسبی / فرضی / ضعیف / آغازنشده / نامربوط.

| لایه             | پرسش                                             |
| ---------------- | ------------------------------------------------ |
| رفتار مشاهده‌شده | پژوهش، داده‌های تحلیلی، یا باور تیم؟             |
| دامنه            | فضای پیش از محصول چقدر خوب فهمیده شده است؟       |
| نیازهای کاربر    | آیا می‌توانید کار (job) و اهمیت آن را بیان کنید؟ |
| راهبرد محصول     | کدام نیاز، کدام نتیجهٔ کسب‌وکار، به‌طور صریح؟    |
| مدل مفهومی       | اشیا و واژگان روشن و مشترک؟                      |
| جریان تعامل      | سفرهای کلیدی با مکان‌ها، گام‌ها و نقاط تصمیم؟    |
| سطح              | سیستم طراحی (design system) یا زبان بصری موجود؟  |

## گلوگاه را پیدا کنید <a id="find-the-bottleneck"></a>

- گلوگاه پایین‌ترین لایه‌ای است که ضعیف، فرضی یا آغازنشده رتبه گرفته است
- آن را نام ببرید، همراه با تصمیم‌های ناموجود و ریسک برای لایه‌های بالاتر
- لایه‌های فرضی را جداگانه علامت بزنید: محکم به نظر می‌رسند و ریسک را
  پنهان می‌کنند
- ضرب‌الاجل‌هایی را که محاسبه را تغییر می‌دهند بپذیرید؛ بده‌بستان را نام
  ببرید

## یک گام بعدی را توصیه کنید <a id="recommend-one-next-step"></a>

- راهنمای لایه‌ای را که باید بعداً روی آن کار شود نام ببرید و دلیلش را
  بگویید
- بپرسید که آیا اکنون اجرا شود یا ابتدا تصویر به چالش کشیده شود

## ثبت کنید <a id="capture"></a>

- جدول بازبینی
- گلوگاه و توصیه، هر کدام در یک خط
