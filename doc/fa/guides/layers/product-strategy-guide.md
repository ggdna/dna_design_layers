# راهنمای راهبرد محصول

لایهٔ ۴ از ۷، نخستین لایهٔ فضای راه‌حل. مهارت:
`/layers-product-strategy`.

## بدانید این لایه چیست <a id="know-what-this-layer-is"></a>

- جایی که فهم به انتخاب تبدیل می‌شود: کدام نیازها پاسخ داده شوند، کدام
  نتیجهٔ کسب‌وکار هدف گرفته شود
- شرط‌بندی‌ها (bets)، نه قطعیت‌ها

## تصمیم بگیرید <a id="decide"></a>

- نتیجهٔ کسب‌وکاری که این کار به آن خدمت می‌کند
- کدام فرصت‌ها (opportunities) به آن نتیجه وصل‌اند
- کدام شرط‌های راه‌حل روی آن‌ها گذاشته می‌شود
- چگونه پرریسک‌ترین فرض ارزان آزموده شود
- کدام شرط‌ها اول می‌آیند، و چرا

## صادق بمانید <a id="keep-it-honest"></a>

- یک نتیجهٔ قابل‌اندازه‌گیری و محدود برای هر درخت
- فرصت‌ها نیازهایی به زبان اول‌شخص‌اند که به لحظه‌ای از سفر کاربر گره
  خورده‌اند، نه قابلیت‌ها؛ آزمون وارونه‌سازی (flip test) را به کار ببرید
- هر فرصت به نتیجه وصل است
- هر شرط پرریسک‌ترین فرض خود را نام می‌برد؛ بیش از یک شرط برای هر فرصت
- هر آزمایش ارزان‌ترین آزمون است: چند روز، نه چند ماه

## یک تکنیک برگزینید <a id="pick-a-technique"></a>

| موقعیت                      | تکنیک                                         |
| --------------------------- | --------------------------------------------- |
| پیش‌فرض                     | درخت فرصت–راه‌حل (opportunity solution tree)  |
| فرصت برگزیده                | شرط‌های راه‌حل به‌همراه آزمایش‌ها             |
| قابلیت‌های نامزد فراوان     | تحلیل کانو (Kano)، سبد کارها (jobs portfolio) |
| انتخاب معیار نتیجه          | HEART، ستارهٔ قطبی (North Star)               |
| نیاز به زمان‌بندی مشترک     | نقشهٔ راه اکنون / بعدی / بعدتر                |
| جایگاه‌یابی، ساختن یا خریدن | نقشه‌برداری Wardley، بسته‌بندی / تفکیک        |
| کدام جریان اول              | سفرهای حیاتی کاربر                            |

## ثبت کنید <a id="capture"></a>

- نتیجه
- درخت فرصت‌ها، گروه‌بندی‌شده بر اساس لحظهٔ سفر
- ۲ تا ۳ شرط برتر با آزمایش‌هایشان
- شرط‌های به تعویق افتاده و فرض‌های آزموده‌نشده

## ادامه دهید <a id="continue"></a>

شرط‌های برگزیده تعیین می‌کنند که در
[مدل مفهومی](conceptual-model-guide.md) چه چیزی بعداً مدل شود. هدف‌ها در
`goals` پوشهٔ فصل جاری `pm/<lang>/<yyyy>-Q<n>` در مخزن PM قرار دارند و تا
زمانی که باز هستند به فصل بعد منتقل می‌شوند؛ نیازمندی‌های برآمده از
شرط‌ها در `requirements` در کنار آن‌ها قرار دارند.
