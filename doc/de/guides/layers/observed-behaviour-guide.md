# Leitfaden zum beobachteten Verhalten

Ebene 1 von 7, Problemraum. Skill: `/layers-observed-behaviour`.

## Wissen, was diese Ebene ist <a id="know-what-this-layer-is"></a>

- Was Nutzer tatsächlich tun, sagten und taten — nicht, was das Team glaubt
- Die Quelle von allem darüber; alle anderen Ebenen deuten sie

## Entscheiden <a id="decide"></a>

- Welche 2–3 Fragen über die Nutzer eine Antwort brauchen
- Welche Belege es gibt und wie verlässlich sie sind
- Wie das Fehlende erhoben wird
- Welche Muster mit Konfidenz gelten, welche Annahmen bleiben

## Ehrlich bleiben <a id="keep-it-honest"></a>

- Nah an den Rohdaten bleiben: Zitate, Handlungen, Gefühle
- Jeden Befund kennzeichnen: beobachtet / abgeleitet / angenommen
- Forschungslücken benennen, statt sie zu überdecken
- Workarounds als starkes Signal werten

## Eine Technik wählen <a id="pick-a-technique"></a>

| Situation                            | Technik                                          |
| ------------------------------------ | ------------------------------------------------ |
| Noch keine Forschung                 | Lernziel festlegen, dann eine Studie             |
| Auslöser und Motive unklar           | JTBD-Interviews zu einem realen vergangenen Fall |
| Sagen weicht vom Tun ab              | Contextual Inquiry, Shadowing                    |
| Bestehendes Produkt                  | Support-Tickets, Analytics, Usability            |
| Material vorhanden                   | Beobachtungen extrahieren, Muster gruppieren     |

## Festhalten <a id="capture"></a>

- Zentrale Rohbeobachtungen mit ihrer Quelle
- Muster mit stützenden Belegen
- Mögliche Job Stories mit Konfidenz
- Benannte Forschungslücken

## Weitermachen <a id="continue"></a>

Die möglichen Job Stories in der Ebene
[Nutzerbedürfnisse](user-needs-guide.md) verfeinern; die gehörten Nomen in
die Ebene [Domäne](domain-guide.md) einspeisen.
