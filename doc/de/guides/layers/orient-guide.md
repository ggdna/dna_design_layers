# Orientierungs-Leitfaden

Die Eingangstür zum Ebenensystem. Skill: `/layers-orient`.

## Wissen, was Orientierung ist <a id="know-what-orient-is"></a>

- Ein schnelles Audit über alle sieben Ebenen, kein tiefer Einstieg in eine
- Beantwortet eine Frage: Welche Ebene braucht am dringendsten
  Aufmerksamkeit?
- Ergebnis: eine kurze Audit-Tabelle und eine Empfehlung

## Drei Fragen stellen <a id="ask-three-questions"></a>

- Um welches Produkt oder Feature geht es?
- Welche Design-Herausforderung hat das ausgelöst?
- Wie weit ist die Arbeit: frühe Erkundung, aktives Design, Reparatur eines
  bestehenden Produkts?

## Jede Ebene prüfen <a id="audit-every-layer"></a>

Pro Ebene ein oder zwei gezielte Fragen stellen und sie bewerten:
stark / teilweise / angenommen / schwach / nicht begonnen / n. a.

| Ebene                  | Frage                                                   |
| ---------------------- | ------------------------------------------------------- |
| Beobachtetes Verhalten | Forschung, Analytics oder Überzeugung des Teams?        |
| Domäne                 | Wie gut ist das Feld vor dem Produkt verstanden?        |
| Nutzerbedürfnisse      | Lässt sich die Aufgabe benennen und warum sie zählt?    |
| Produktstrategie       | Welches Bedürfnis, welches Geschäftsergebnis, explizit? |
| Konzeptmodell          | Klare, gemeinsame Objekte und Begriffe?                 |
| Interaktionsablauf     | Kernwege mit Orten, Schritten, Entscheidungspunkten?    |
| Oberfläche             | Bestehendes Design-System oder visuelle Sprache?        |

## Den Engpass finden <a id="find-the-bottleneck"></a>

- Der Engpass ist die unterste Ebene, die als schwach, angenommen oder
  nicht begonnen bewertet ist
- Ihn benennen, die fehlenden Entscheidungen und das Risiko für die Ebenen
  darüber
- Angenommene Ebenen gesondert markieren: Sie wirken solide und verbergen
  das Risiko
- Deadlines anerkennen, die die Abwägung verändern; den Kompromiss benennen

## Einen nächsten Schritt empfehlen <a id="recommend-one-next-step"></a>

- Den Ebenen-Leitfaden nennen, mit dem als Nächstes gearbeitet wird, und
  warum
- Fragen, ob er jetzt ausgeführt oder das Bild zuerst hinterfragt werden
  soll

## Festhalten <a id="capture"></a>

- Die Audit-Tabelle
- Den Engpass und die Empfehlung, je eine Zeile
