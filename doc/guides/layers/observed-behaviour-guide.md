# Observed behaviour guide

Layer 1 of 7, problem space. Skill: `/layers-observed-behaviour`.

## Know what this layer is

- What users actually do, said and did — not what the team believes
- The source of everything above; all other layers interpret it

## Decide

- Which 2–3 questions about users need an answer
- Which evidence exists and how reliable it is
- How to gather what is missing
- Which patterns hold with confidence, which stay assumptions

## Keep it honest

- Stay close to raw data: quotes, actions, feelings
- Mark every finding: observed / inferred / assumed
- Name research gaps instead of papering over them
- Treat workarounds as strong signal

## Pick a technique

| Situation                        | Technique                              |
| -------------------------------- | -------------------------------------- |
| No research yet                  | Define the learning goal, then a study |
| Triggers and motivations unclear | JTBD interviews about a real past case |
| Saying differs from doing        | Contextual inquiry, shadowing          |
| Existing product                 | Support tickets, analytics, usability  |
| Material exists                  | Extract observations, group patterns   |

## Capture

- Key raw observations with their source
- Patterns with supporting evidence
- Candidate job stories with confidence
- Named research gaps

## Continue

Refine the candidate job stories in the [user needs](user-needs-guide.md)
layer; feed the nouns you heard into the [domain](domain-guide.md) layer.
