# Leitfaden zur Oberfläche

Ebene 7 von 7, Lösungsraum. Skill: `/layers-surface`.

## @layer Wissen, was diese Ebene ist <a id="know-what-this-layer-is"></a>

- Hier wird alles Darunterliegende zu dem, was ein Mensch erlebt: Worte,
  Bilder, Bewegung, Rückmeldung
- Probleme der Oberfläche sind oft Symptome tieferer Ebenen

## @decide Entscheiden <a id="decide"></a>

- Ob die Oberfläche das Vokabular und die Objekte des Modells respektiert
- Ob jede Affordanz des Breadboards vorhanden ist und nichts ohne Modell
  dahinter existiert
- Ob der emotionale Ton zu den Jobs der Nutzer passt
- Wie Nutzer erfahren, was passiert ist, gerade läuft oder fehlgeschlagen
  ist
- Was am stärksten hervortritt, und ob es das sollte
- Ob alles für die Nutzer zugänglich ist, die es brauchen

## @honest Ehrlich bleiben <a id="keep-it-honest"></a>

- Oberflächen-Korrekturen von tieferen Problemen unterscheiden; tiefere an
  ihre Ebene zurückgeben
- Begriffe stimmen mit der Ubiquitous Language überein
- Keine Gestaltwandler, keine maskierten Objekte
- Fehlermeldungen diagnostizieren, erklären und bieten einen Ausweg an
- Hervorhebung spiegelt Wichtigkeit
- Barrierefreiheit wird entschieden, nicht den Voreinstellungen überlassen

## @technique Eine Technik wählen <a id="pick-a-technique"></a>

| Situation                         | Technik                                        |
| --------------------------------- | ---------------------------------------------- |
| Begriffe wirken falsch            | Vokabular-Prüfung                              |
| Dasselbe Objekt sieht anders aus  | Prüfung der Objekt-Konsistenz                  |
| Etwas fehlt oder ist zu viel      | Vollständigkeitsprüfung gegen das Breadboard   |
| Ton passt nicht                   | Prüfung des emotionalen Tons                   |
| Nutzer unsicher, was passiert ist | Inventar von Rückmeldungen und Fehlern         |
| Zu viel konkurriert               | Prüfung der Hierarchie                         |
| Den Voreinstellungen überlassen   | Durchgang zur Barrierefreiheit                 |
| Oberfläche erstellen              | Mockups, Style Tiles, Prototypen, Texte zuerst |

## @capture Festhalten <a id="capture"></a>

- Befunde, jeweils markiert als Oberflächen-Korrektur oder Problem einer
  tieferen Ebene
- Offene Oberflächen-Entscheidungen mit Optionen und Randbedingungen
- Ebenenübergreifende Probleme, die zuerst zu lösen sind
- Was bereits gut funktioniert
