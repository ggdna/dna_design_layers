# Leitfaden zur Produktstrategie

Ebene 4 von 7, erste Ebene des Lösungsraums. Skill:
`/layers-product-strategy`.

## @layer Wissen, was diese Ebene ist <a id="know-what-this-layer-is"></a>

- Hier wird Verständnis zu Entscheidungen: welche Bedürfnisse bedient,
  welches Geschäftsergebnis angestrebt wird
- Wetten, keine Gewissheiten

## @decide Entscheiden <a id="decide"></a>

- Das Geschäftsergebnis, dem diese Arbeit dient
- Welche Chancen mit diesem Ergebnis verbunden sind
- Welche Lösungswetten auf sie gesetzt werden
- Wie die riskanteste Annahme günstig getestet wird
- Welche Wetten zuerst kommen, und warum

## @honest Ehrlich bleiben <a id="keep-it-honest"></a>

- Ein messbares, begrenztes Ergebnis pro Baum
- Chancen sind Bedürfnisse in der Ich-Form, verankert in einem Moment der
  Customer Journey, keine Features; den Umkehrtest anwenden
- Jede Chance ist mit dem Ergebnis verbunden
- Jede Wette nennt ihre riskanteste Annahme; mehr als eine Wette pro
  Chance
- Jedes Experiment ist der günstigste Test: Tage, nicht Monate

## @technique Eine Technik wählen <a id="pick-a-technique"></a>

| Situation                         | Technik                               |
| --------------------------------- | ------------------------------------- |
| Standard                          | Opportunity Solution Tree             |
| Gewählte Chance                   | Lösungswetten plus Experimente        |
| Viele mögliche Features           | Kano-Analyse, Jobs-Portfolio          |
| Ergebnis-Metrik wählen            | HEART, North Star                     |
| Gemeinsamer Zeitplan nötig        | Now / Next / Later-Roadmap            |
| Positionierung, bauen oder kaufen | Wardley Mapping, Bündeln / Entbündeln |
| Welcher Ablauf zuerst             | Kritische Nutzerwege                  |

## @capture Festhalten <a id="capture"></a>

- Das Ergebnis
- Den Chancenbaum, gruppiert nach Moment der Customer Journey
- Die wichtigsten 2–3 Wetten mit ihren Experimenten
- Zurückgestellte Wetten und ungetestete Annahmen

## @continue Weitermachen <a id="continue"></a>

Die gewählten Wetten legen fest, was als Nächstes im
[Konzeptmodell](conceptual-model-guide.md) modelliert wird. Ziele stehen in
`goals` des aktuellen Quartalsordners `pm/<lang>/<yyyy>-Q<n>` des PM-Repos
und werden ins nächste Quartal übernommen, solange sie offen sind; die aus
den Wetten abgeleiteten Anforderungen stehen daneben in `requirements`.
