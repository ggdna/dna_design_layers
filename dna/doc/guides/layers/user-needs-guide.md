# User needs guide

Layer 3 of 7, problem space. Skill: `/layers-user-needs`.

## Know what this layer is

- What users try to achieve, and why — an interpretation of observed
  behaviour and domain knowledge
- Output: opportunities — needs, pains, desires

## Decide

- Who exactly the users are, and in which situation
- Which jobs they do: functional, emotional, social
- Which needs are grounded, which are assumed
- Which needs matter most, and why

## Keep it honest

- State the need, not the solution; push past "I want to export CSV"
- Strip the mechanism: the "when" must not name your current system
- Make the "when" picturable: an event, a feeling, a threshold
- Ask for emotional and social jobs explicitly
- Mark confidence: observed / inferred / assumed

## Pick a technique

| Situation             | Technique                                  |
| --------------------- | ------------------------------------------ |
| Default               | Job stories: when, I want, so I can        |
| Team works role-based | User stories                               |
| Large user base       | Top tasks analysis                         |
| Stakeholder alignment | Persona plus scenario                      |
| Measurability matters | ODI desired outcomes                       |
| Many needs            | Prioritise: importance × how poorly served |

## Capture

- Prioritised needs with confidence
- Surfaced but unprioritised needs
- Gaps and contradictions between user types
