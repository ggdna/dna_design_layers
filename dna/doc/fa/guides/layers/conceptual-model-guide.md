# راهنمای مدل مفهومی

لایهٔ ۵ از ۷، فضای راه‌حل. مهارت: `/layers-conceptual-model`.

## @layer بدانید این لایه چیست <a id="know-what-this-layer-is"></a>

- اشیایی که محصول می‌شناسد، روابط، وضعیت‌ها و واژگانشان — مستقل از هر
  رابط کاربری
- نادیده‌گرفته‌ترین لایهٔ باربر؛ بیش از آنچه راحت به نظر می‌رسد به آن توجه
  کنید
- نه مدل ذهنی کاربران، نه طرح‌وارهٔ پایگاه داده

## @decide تصمیم بگیرید <a id="decide"></a>

- کدام اشیا وجود دارند و مرزهایشان کجاست
- اشیا چگونه به هم مربوط‌اند: کاردینالیتی و نقش‌های نام‌دار
- کاربر با هر شیء چه کاری می‌تواند بکند
- کدام وضعیت‌ها و گذارها اهمیت دارند
- یک نام برای هر مفهوم، یک مفهوم برای هر نام

## @honest صادق بمانید <a id="keep-it-honest"></a>

- فقط اشیای واقعی: نمونه‌پذیر، ساختارمند، سودمند؛ «CAC» نمونه‌ای از Metric
  است
- ویژگی‌ای را که شیء دیگری را نام می‌برد به‌صورت رابطه مدل کنید
- بدون افزوده‌های گمانه‌زنانه؛ هر عنصر به نیازی بیان‌شده برمی‌گردد
- «می‌تواند شیء باشد» یعنی «باید شیء درجه‌یک باشد» نیست؛ ماندگاری را با
  یک جریان مشخص توجیه کنید، شرط‌ها را موقت علامت بزنید
- فعل‌های کلی را که پیامدهای متفاوتی پنهان می‌کنند جدا کنید: اصلاح یک
  نشانی در برابر ثبت یک جابه‌جایی
- صحبت از پیاده‌سازی را به سمت آنچه کاربر می‌تواند انجام دهد هدایت کنید

## @technique یک تکنیک برگزینید <a id="pick-a-technique"></a>

| موقعیت                                 | تکنیک                                       |
| -------------------------------------- | ------------------------------------------- |
| مادهٔ خام برای کاوش                     | جست‌وجوی اسم‌ها (noun foraging)، OOUX         |
| یک شیء نامشخص                          | تعریف شیء                                   |
| شیء بودن نامطمئن                       | اول جریان را طرح بزنید، سپس صوری کنید       |
| روابط برای بررسی                       | نقشهٔ رابطه‌ای اشیا (`erDiagram`)            |
| وضعیت آنچه مجاز است را تغییر می‌دهد     | نمودار وضعیت (`stateDiagram-v2`)            |
| فعل‌ها ناسازگار                         | فهرست کنش‌ها در همهٔ اشیا                    |
| نام‌گذاری مورد مناقشه                   | فهرست زبان فراگیر (ubiquitous language)     |
| بازطراحی                               | محصول موجود را مرور کنید                    |

تصمیم‌های زمانی را بکاوید: وضعیت‌های میانی، تأخیر خواندن، رابطه در گذر
زمان، معنای حذف، تاریخچه.

## @capture ثبت کنید <a id="capture"></a>

- تعریف‌های قطعی اشیا، با علامت‌گذاری تعریف‌های موقت
- نمودارهایی که یک رابطه یا چرخهٔ عمر واقعی را بیان می‌کنند
- تصمیم‌های واژگانی همراه با گزینه‌های ردشده
- پرسش‌های باز برای مهندسی

## @continue ادامه دهید <a id="continue"></a>

وقتی اشیا و کنش‌ها پایدار شدند، طراحی کنید که کاربران چگونه میان آن‌ها
حرکت می‌کنند: [جریان تعامل](interaction-flow-guide.md).
