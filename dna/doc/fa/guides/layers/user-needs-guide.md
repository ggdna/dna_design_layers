# راهنمای نیازهای کاربر

لایهٔ ۳ از ۷، فضای مسئله. مهارت: `/layers-user-needs`.

## @layer بدانید این لایه چیست <a id="know-what-this-layer-is"></a>

- کاربران به دنبال رسیدن به چه چیزی هستند، و چرا — تفسیری از رفتار
  مشاهده‌شده و دانش دامنه
- خروجی: فرصت‌ها — نیازها، دردها، خواسته‌ها

## @decide تصمیم بگیرید <a id="decide"></a>

- کاربران دقیقاً چه کسانی هستند، و در چه موقعیتی
- چه کارهایی (jobs) انجام می‌دهند: کارکردی، عاطفی، اجتماعی
- کدام نیازها مستند هستند و کدام فرضی
- کدام نیازها بیشترین اهمیت را دارند، و چرا

## @honest صادق بمانید <a id="keep-it-honest"></a>

- نیاز را بیان کنید، نه راه‌حل را؛ از «می‌خواهم CSV صادر کنم» فراتر بروید
- سازوکار را حذف کنید: «وقتی» نباید سیستم فعلی شما را نام ببرد
- «وقتی» را قابل‌تصور کنید: یک رویداد، یک احساس، یک آستانه
- صریحاً دربارهٔ کارهای عاطفی و اجتماعی بپرسید
- میزان اطمینان را مشخص کنید: مشاهده‌شده / استنباط‌شده / فرضی

## @technique یک تکنیک برگزینید <a id="pick-a-technique"></a>

| موقعیت                        | تکنیک                                          |
| ----------------------------- | ---------------------------------------------- |
| پیش‌فرض                       | داستان‌های کار (job stories): وقتی، می‌خواهم، تا بتوانم |
| تیم مبتنی بر نقش کار می‌کند   | داستان‌های کاربر (user stories)                 |
| پایگاه کاربری بزرگ            | تحلیل وظایف برتر (top tasks)                   |
| هم‌راستایی ذی‌نفعان            | پرسونا به‌همراه سناریو                          |
| اندازه‌پذیری مهم است          | نتایج مطلوب ODI (desired outcomes)            |
| نیازهای فراوان                | اولویت‌بندی: اهمیت × میزان ضعف پاسخ‌گویی        |

## @capture ثبت کنید <a id="capture"></a>

- نیازهای اولویت‌بندی‌شده با میزان اطمینان
- نیازهای آشکارشده اما اولویت‌بندی‌نشده
- شکاف‌ها و تناقض‌ها میان انواع کاربران

## @continue ادامه دهید <a id="continue"></a>

نیازها فرصت‌های [راهبرد محصول](product-strategy-guide.md) هستند. اگر
بیشترشان فرضی‌اند، ابتدا به [رفتار مشاهده‌شده](observed-behaviour-guide.md)
بازگردید.
